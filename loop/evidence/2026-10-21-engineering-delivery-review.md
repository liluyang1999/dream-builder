## 修复与责任边界

- React 接管入口和场景模块的延迟加载，下载失败进入可恢复错误界面；切换场景清空旧选择，
  过期详情不能覆盖新选择，场景返回值必须匹配请求 seed，长按快捷键不重复触发一次性操作。
- Rust 的生成、设置保存和场景导出进入阻塞工作线程。设置只有一份原生内存快照，按
  “验证、完整文件替换、内存提交”更新；失败保留旧状态。相邻临时文件由资源所有者清理。
- 并发生成领取请求编号，旧任务不能覆盖最新场景；动态光效跟随已提交场景，不被较晚保存的旧设置切换。
  原生入口拒绝超出 JavaScript 安全整数范围的 seed。移除了重复的设置插件缓存。
- 发布文件先在暂存目录独立验证，再替换旧候选；隐藏文件、额外目录、链接与不完整文件集均拒绝。
  来源指纹共用一个实现；卸载检查必须接收真实安装路径并核对快捷方式目标。
- NSIS 能比较两段式显示版本，静默路径也重新读取已装版本并拒绝降级或无效版本。
  完整打包曾复现插件注册晚于钩子加载的错误；调整注册顺序后，完整模板编译及原生测试通过。
- 新增固定清单的 `clean:preview` / `clean`，保留源码、依赖、交付文件和玩家数据；
  清理前预检整份计划，拒绝祖先或后代中的链接。Rust 工具链固定为 1.97.0。

## 安装与独立程序

使用完整 Tauri Release 构建，不依赖 Vite 服务。当前 Windows 账户先核实没有已安装程序，
再安装到项目内带空格的临时目录。版本 1.0、安装位置、主程序、卸载器及两份快捷方式全部通过检查。
安装版和便携 EXE 分别完成真实森林 UI、IPC、无效设置拒绝、单实例、正常退出与重启恢复。
两次运行的时间和二进制 SHA-256 见 [原生运行记录](2026-10-21-native-runtime.json)。

同版静默重装成功。仅对本轮安装的登记项暂时设置较新版本和无效版本，再运行实际安装器：
均以退出码 2 拒绝，已装 EXE 哈希不变；登记值立即恢复。该检查验证拒绝策略，**不是**真实旧版本升级迁移。
最后运行真实卸载器；独立检查确认卸载项、程序目录、快捷方式和运行进程均为零，原有玩家设置保留。

测试使用独立 WebView2 目录。正式设置只在内存中备份，结束后逐字节和修改时间复核恢复；
本次新建的日志目录已清理。隔离测试标识的资料目录也已移除，测试服务和端口已停止。
便携与安装版 EXE 的三个字节差异是 Tauri 的 `UNK` / `NSS` 包类型标记，因此分别记录哈希。
后续重建必须以交付清单核对实际文件身份，不能沿用这里的哈希而不比较。
