# 首个垂直切片：十分钟森林复苏

## 体验脚本

1. **0:00–1:00，醒来。** 玩家出现在智慧树根部，镜头用一段很短的可跳过引导展示失色的树冠；脚边第一枚光种教会移动与互动。
2. **1:00–4:00，学会寻找。** 发光飞蛾与草叶朝向指向蘑菇坡。玩家绕过倒木，收集第二枚光种，并看到远处遗迹门回应。
3. **4:00–7:00，做出选择。** 溪流与遗迹两条短路线都通往第三枚光种；一条更直观，另一条藏有记忆碎片，最后在净化节点汇合。
4. **7:00–9:00，净化。** 玩家把三枚光种注入节点，完成一个轻量的方向/节奏谜题；失败只重置局部谜题，不扣除资源。
5. **9:00–10:00，世界回应。** 色彩沿根系返回智慧树，树冠展开、动物出现、音乐增加一层，遗迹门为下一章开启。游戏保存并把镜头控制交还玩家。

## M1 系统合同

### 玩家运动

- `WASD`/方向键生成相机相对的二维移动意图；对角线归一化，不获得额外速度。
- 行走、奔跑、转向、加速与减速参数集中配置，不散落在组件中。
- 第一版角色是低多边形占位“森林精灵”，碰撞体采用半径 + 高度近似。
- 运动采用固定最大步长并分段推进，避免低帧率时穿过薄障碍。
- `R` 将玩家和相机恢复到最近安全点，而不只重置观察相机。

### 第三人称相机

- 相机围绕玩家，默认在角色后上方；水平旋转自由，俯仰和距离有限制。
- 移动方向基于相机水平前向量；相机俯仰不改变玩家地面速度。
- 第一版用射线/球形近似缩短相机距离，防止穿入关键障碍；没有遮挡时平滑恢复。
- `prefers-reduced-motion` 或游戏设置开启时降低相机滞后、摇晃与冲刺 FOV 变化。

### 灰盒林地与碰撞

- 地面先使用可测试的高度函数或平面分区；关键边界由显式圆形/轴对齐矩形障碍描述。
- 中央树干、倒木、遗迹墙和世界边界必须碰撞；小草、粒子和装饰石不碰撞。
- 出生点和重置点必须经过可行走校验，不能落在障碍内。
- 世界布局数据与网格呈现分开，同一布局既能被运动测试消费，也能由 R3F 绘制。

## M2 状态机

> 实现状态：状态机、五处安全检查点、单段记忆、v1→v2 迁移和四拍方向净化均已进入灰盒版本，并通过单元测试与真实 Chromium 流程验证；目标 Windows 设备的连续十分钟 Tauri/Rust 报告已覆盖 `scene-load` 与 `cleansing` 并通过性能门禁。下方 5 名首次接触玩家的无提示观察仍待完成。

```text
unseen → revealed → collected
                    three seeds collected
                            ↓
node dormant → ready → cleansing → restored
                                      ↓
tree stage 0 → stage 1 + chapter gate unlocked
```

状态转换必须是纯函数并拒绝非法跳转。R3F 动效响应已提交状态，不负责决定是否完成。存档至少包含版本、当前检查点、已收集光种、节点状态、智慧树阶段和已读记忆；保存失败必须提示，但不能让当前会话立刻丢失。

## 可玩性验收

具体主持话术、新档准备、单次记录表和汇总规则见 [M2 无提示可玩性观察协议](m2-playtest.md)。

- 首次接触项目的人无需开发者解释即可在 12 分钟内完成主流程。
- 至少 4/5 名观察者能在 90 秒内找到第一条路线，且不会把 seed 输入/导出按钮误认为主目标。
- 玩家从任意可达位置都能回到中央树，不存在无法自行恢复的卡死点。
- 每次关键交互至少有两种反馈通道（例如视觉 + 声音，或动画 + HUD），并支持减弱动态效果。
- 在项目规定的目标 Windows 设备上记录 10 分钟帧时间；M2 灰盒基线为平均不低于 55 FPS、1% Low 不低于 30 FPS、超过 50 ms 的帧不多于总帧数的 1%，且人工未观察到持续卡顿；加载和净化峰值需要单独标注。

内置记录器从 `?` 帮助页的“性能记录”进入。它在十分钟后自动停止，可提前停止并导出带版本号的 JSON；报告包含平均 FPS、1% low 等价值、P50/P95/P99/最长帧、慢帧计数、draw calls/三角形/资源/可用 JS 堆峰值、首个场景帧时间，以及 `scene-load` 与 `cleansing` 区间。`scene-load` 会覆盖数据就绪后的 1 秒稳定窗口，使新几何首次提交也进入加载统计。记录器只保留固定大小直方图与最多 128 个状态标记，不保留逐帧样本或玩家路径。它测得的是浏览器主循环观察到的帧间隔，不是 GPU 帧时间；浏览器冒烟报告也不能替代 Tauri 目标设备证据。

五次观察与性能 JSON 使用显式开发地址 `?tool=m2-evidence` 打开本地 M2 证据工作台进行汇总。该入口不出现在玩家 HUD，不联网、不接受逐帧样本，也不会自动采集姓名、账号、原始输入或玩家路径；它只负责按上述门槛判定真实证据，不能替代真人观察。

## 暂缓项

战斗、敌人 AI、物品栏、复杂任务树、多人联机、动态天气、昼夜模拟、程序化无限地图和完整角色定制都不属于首个垂直切片。只有核心循环经观察证明有趣后，才为其中某项建立独立设计与预算。
