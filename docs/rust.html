Rust backend

Rust 后端：领域模型、确定性生成与原生副作用

Rust 部分同时是库和可执行程序。main.rs 保持极薄，只调用库的 run()； 可测试逻辑放在 domain、generation、magic 和 state 中，Tauri 命令只做边界适配。

domain/Vec3、Seed、Energy、树场景、细节、魔法场和 builder；只表达数据与不变量。
generation/RNG trait、SeededRng、SceneGenerator trait 与 FantasyTreeGenerator；给定 seed 可重放。
state.rs设置、seed 历史、活动 seed 与场景缓存，封装在 Arc<Mutex<Inner>>。
commands.rs七个薄 IPC 命令；输入校验、状态访问、异步导出与结构化错误。
lib.rs插件、菜单、setup、托管状态、后台事件、命令注册和进程生命周期。

所有权与借用

只读取 id 的函数接收 &str，生成器借用 &mut impl Rng； 只有返回或跨线程/状态边界时才拥有并克隆数据。克隆不是“让借用检查器安静”的默认工具。

Newtype 与不变量

Seed(u64) 防止任意数字混用；Energy(f32) 只能通过夹紧构造， 因而任何已存在的 Energy 都落在 0..1。serde transparent 保持 wire 仍是数字。

Trait 与泛型接缝

Rng 只要求实现 next_u32，默认方法派生浮点与范围； SceneGenerator 定义生成与细节查询，使调用方依赖能力而不是具体算法。

Builder 与枚举

TreeSceneBuilder 用移动 self 的链式 API 组装结果；DetailKind 与 AppError 用穷尽 match，让新增变体在遗漏处理处产生编译错误。

错误处理

AppError 由 thiserror 派生错误文本， 并手写 Serialize 稳定输出 { code, message }。可预期失败返回 Result 并用 ? 传播；panic 只代表不变量或启动级错误。panic hook 会把崩溃写入日志， 但绝不能把秘密或用户数据塞进错误文本。

共享状态与异步纪律

AppState 克隆的是 Arc，不是复制状态。 每个方法内部短暂加锁，复制所需值后立即释放。事件任务 在 interval.tick().await 之后才读取设置，绝不让同步 Mutex guard 跨越 await。 文件导出使用 tokio::fs::write，避免阻塞异步执行器线程。

详情查询为什么不用重新生成整棵树

生成场景时已经包含叶簇、符文和水晶的说明。detail_info 先按 seed 核对缓存， 找到对象后只复制这一条说明；未命中时才走确定性生成。这样点击已有对象不会重复计算树枝、树叶和随机序列。 缓存仍只保留一个场景，不随玩家探索无限增长，也不改变活动 seed 或历史。

持久化：读尽力而为，写必须报告失败

persistence.rs 通过 Store 插件的扩展 trait StoreExt 使用插件能力——这是 Tauri 插件在 Rust 侧的惯用形态：插件为 AppHandle 增加方法，而不是要求你自己持有一个全局对象。设置落在 settings.json 的 settings 键下。

读：三层回退

打不开 store、反序列化失败、或反序列化成功但 validate() 不通过，三种情况都返回默认设置。 玩家宁可看到默认主题，也不能因为一个坏文件启动不了游戏。

写：结构化错误

每一步都用 map_err 转成 AppError::Persistence 并带上原因， 再由 ? 传播。写失败必须让前端知道，不能返回 Ok 假装保存成功。

注意这里的非对称：读可以静默降级，写不可以。 读失败的后果是“设置回到默认”，玩家立刻看得见也能改回来； 写失败的后果是“玩家以为改好了，下次启动全部丢失”，只有报告出来才能补救。 同一条原则也出现在前端存档层——加载可以回退到备份，保存失败必须提示。 设置命令按“校验 → 持久化 → 提交内存”执行；磁盘保存失败时，原生内存仍保留上次提交的设置。 这保证的是内存提交顺序，文件替换与断电恢复仍由 Store 插件的具体持久化机制决定。

整数边界不能靠运气避开

闭区间 [min, max] 的宽度是 max - min + 1。 整个 u32 区间有 2 的 32 次方个值，宽度本身装不进 u32，所以先用 u64 算宽度再映射回范围。 rng.rs 的测试包含完整区间和单点最大值， 同时保留旧种子在普通范围内的序列，防止修边界时意外改变整片森林。

确定性生成

SeededRng 的输出只由 seed 与调用序列决定；FantasyTreeGenerator 依序生成树干、树冠、符文和水晶， 细节 id 也稳定。确定性让缓存、导出、故障复现、测试和跨会话重建成立。任何“为了视觉随机”而读取系统时间或 平台随机源都会破坏这条合同；需要会话变化时，应显式引入独立 seed 并把它纳入存档。
