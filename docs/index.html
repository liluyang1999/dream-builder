Reading guide

怎样使用这份档案

先建立“谁负责什么”的心智模型，再沿一条真实请求进入代码。每个概念都按 “是什么、为什么在这里使用、代码在哪里、容易犯什么错”来解释。路径链接指向仓库内真实文件； 版本、性能与发布结论都区分自动化证据和仍需人工完成的外部门槛。

第一次阅读

依次读“项目现状 → 总体架构 → 运行全链路”，先理解双运行时、数据边界和游戏循环。

前端学习

从 TypeScript/React、状态机、第三人称运动到 R3F 场景，边读边运行 pnpm dev。

桌面与 Rust 学习

从 IPC 契约进入 Rust 命令，再看 Tauri Builder、权限、WebView2 与 NSIS 发布。

事实边界：当前代码已经形成完整的短篇单章游戏和 Windows 候选包工程， 但五名首次接触玩家观察、实体手柄完整听测、干净账户覆盖升级以及受信任代码签名仍是外部证据。 自动化全部通过也不能替代这些发布门槛。最新产品口径见 loop/product/README.md。

Guided learning

建议的七段学习路线

  1. 先运行浏览器版：pnpm dev，完成标题到净化，观察没有 Rust 时的回退警告。
  2. 读纯规则：从 gameProgress、purificationPuzzle、playerInput、playerMotion 的测试开始，理解确定状态转换。
  3. 接上 React：追踪 store → GameplayController → UI/Scene，观察组件怎样消费同一快照。
  4. 进入 3D：从 SceneCanvas 到 GameplayWorld，再拆解 TreeContent、CartoonForest、实例化、shader 和性能探针。
  5. 练习无障碍：只用键盘走一遍标题—设置—帮助—净化，再打开系统“减少动态”对比表现差异。
  6. 跨过 IPC：比较 Zod schema 与 Rust serde struct，跟踪 generate_tree 请求和 magic-field 事件。
  7. 运行原生与发布：pnpm tauri dev 验证 WebView2/IPC，再阅读 capability、CSP、构建分块、CI 工作流、发布清单和安装状态脚本。
一次安全练习：给 IPC 场景增加一个可选、向后兼容字段。先写 Rust/TS 两侧失败测试， 再同步 domain、serde、Zod、Worker 和消费者，最后运行全部门禁。这个练习会触及本项目最重要的架构边界。
