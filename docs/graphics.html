Realtime graphics and audio

3D 世界：React 声明场景，Three 执行渲染

react-three-fiber（R3F）不是另一套 3D 引擎；它是 Three.js 的 React renderer。 JSX 描述场景图，R3F 把 <mesh>、材质、光源和相机映射为 Three 对象， 最终仍由 WebGL 在 WebView2 中绘制。

Canvas

SceneCanvas 配置相机、DPR、色调映射、场景 API、后处理和截图所需的 drawing buffer。

世界

GameplayWorld 组合玩家、卡通森林、光种、记忆、检查点和净化节点。

智慧树

TreeContent 把 Rust 返回的枝干、叶簇、符文、水晶与地面光环组合为场景。

程序化森林

CartoonForest 按 seed 和质量档生成可重建装饰，但关键路径与碰撞保持稳定。

粒子

MagicParticles 用 BufferGeometry 和 useFrame 更新位置，从 ref 读取后端场。

后处理

Bloom 只服务发光物体；画质档与减少动态控制成本和强度，不能让装饰破坏目标可读性。

关键图形概念

实例化与 draw call

每棵草、每片叶都单独 mesh 会产生大量 draw call。叶簇等重复物体使用 InstancedMesh：共享几何和材质，只为每个实例提供变换矩阵。它牺牲部分逐对象自由， 换来显著减少 CPU 提交开销。

材质、色调映射与 Bloom

PBR 材质根据光照计算表面；emissive 让对象自身发亮；ACES 色调映射把 HDR 亮度压回屏幕范围； Bloom 再把超过阈值的亮部扩散。三者顺序和曝光共同决定“发光”是否通透而不糊成一片。

GLSL 水晶与 Fresnel

crystalMaterial.ts 在顶点阶段传递视图法线和视线方向，在片元阶段以 pow(1 - dot(normal, viewDir), power) 形成掠射角更亮的 Fresnel 边缘， 再用时间 uniform 制作流光。hover 与选中只调 uniform，不重建材质。

第三人称相机

PlayerController 维护玩家后上方偏移，把相机和 target 随玩家位移一起平移；移动方向只取相机 水平前向，俯视不会让角色钻入地面。减少动态模式降低相机滞后和强反馈，保证舒适性。

液态玻璃 UI 是一个独立的可复用包

@dream-builder/liquid-glass 不是散落在应用里的几条 CSS，而是 有明确导出面的工作区包。 它演示了一个小型 React 组件库该有的样子：一个上下文 Provider、一个承担全部视觉的基元， 以及几个语义化包装。

导出角色
GlassProvider / useGlass用 Context 向下传递主题与质量档，避免每个组件各自探测环境
GlassSurface唯一真正实现玻璃外观的基元，其余组件都由它组合而来
GlassPanel · GlassCard · GlassButton · GlassBadge语义化包装：调用方表达“这是一个面板/卡片/按钮”，而不是拼装视觉参数
theme.ts只导出 GlassTheme 与 GlassQuality 两个字面量联合，是包的公共词汇表
detectGlassQuality按运行环境能力选择画质档
liquid-glass.css半透明 tint、backdrop-filter、边缘高光与阴影；由入口自动注入

能力探测：先问环境，再决定效果

不支持 backdrop-filter        → low      （不透明回退，完全放弃模糊）
  prefers-reduced-motion 生效   → balanced （保留模糊与高光，去掉流光）
  硬件并发 ≤ 4                  → balanced （低核设备不做最贵的一层）
  其余                          → high

这段逻辑值得单独理解：它探测的是能力与偏好，不是浏览器名称。 CSS.supports() 回答“这个属性能用吗”，matchMedia 回答“用户想要什么”， navigator.hardwareConcurrency 回答“这台机器有多少核”。 三者都不需要维护一张浏览器黑名单，因此不会随 WebView2 的 Evergreen 更新而失效。 服务端或无 window 环境直接返回 balanced，让组件在测试中也有确定行为。

降级不是“变难看”，是“仍然可读”： low 档换成稳定的不透明面板，文字对比度反而更高。 视觉效果永远不能成为可读性的前置条件——这也是它和游戏内“高对比”开关能叠加生效的原因。

程序化音频

forestAudio.ts 使用 Web Audio API 合成环境层， progressAudio.ts 将进度差异映射为短声效。 AudioDirector 在首次用户手势后安全恢复 AudioContext，分别应用主音量、环境音和效果音；静音与页面卸载必须释放节点， 避免后台声音和资源泄漏。
