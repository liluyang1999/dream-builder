Accessibility and input devices

无障碍不是附加皮肤，输入设备也不只有键盘

单机离线游戏同样要面对“看不清、不能久盯动画、只用键盘、只用手柄”的玩家。 本项目把无障碍表达成受校验的设置项、根节点状态类和可测试的输入适配层， 而不是散落在各个组件里的临时判断。

设置类型与范围它真正改变什么
reducedMotion布尔降低相机滞后、粒子幅度与强闪反馈，但保留状态可读性
highContrast布尔根节点加 app-root--high-contrast，提高玻璃面板与次要文本对比
textScalenormal / large根节点加 app-root--large-text，放大 HUD 与覆盖层字号
showHints布尔控制新手提示是否出现，让熟练玩家清空界面
cameraSensitivity整数 50–150缩放相机响应，照顾晕动敏感与精细操作
masterVolume 等整数 0–100主/环境/效果三条独立音量，可完全静音仍可通关

这些字段和 seed、theme 在 同一个 settingsSchema 中定义并带默认值， 因此“无障碍设置”与其他设置走完全相同的校验、IPC 与持久化路径：Rust 侧先验证范围， 再写入 Tauri Store；前端 App.tsx 只把已提交的切片映射为根节点类名。 旧存档缺字段时由 schema 默认值补齐，不会让界面进入半初始化状态。

系统偏好与游戏内设置并存： styles.css 同时响应 @media (prefers-reduced-motion: reduce)。操作系统已经声明“减少动态”时不需要玩家再找一次开关， 而游戏内开关又允许在系统未声明时单独降低动效。两者是“或”的关系，不是互相覆盖。

三种输入设备，两种事件模型

键盘：事件驱动

useKeyboardShortcuts 只在 window 上绑定一次监听，处理函数存在 ref 中，因此既没有陈旧闭包，也不会每次渲染都重新订阅。

指针：事件驱动

useInteractive 把 R3F 的 pointer 事件转成选择 reducer 的动作，悬停与选中仍是纯状态转换。

手柄：轮询驱动

Gamepad API 不提供按钮/摇杆事件，只能读取快照。 GamepadNavigator 在 requestAnimationFrame 中采样，并与上一帧比较做边沿检测。

差异被限制在适配层：三类设备最终都产生同一套意图（移动向量、互动、冲刺、暂停、方向）， 由 playerInput.ts 归一化后交给纯逻辑。 边沿检测尤其重要——长按手柄按键在每一帧都是“按下”，若不比较上一帧状态，一次按压会被当成上百次暂停切换。

模态焦点：Tab 不能逃出对话框

  • useModalFocus 打开时聚焦首个控件，关闭时把焦点还给触发它的控件。
  • Tab / Shift+Tab 在对话框内循环，键盘用户不会“掉”到被遮挡的 HUD 上。
  • Esc 与 ? 优先交给当前对话框，而不是全局游戏快捷键。
  • 全局快捷键遇到 [aria-modal="true"]、输入框或可编辑元素时主动让路，避免“打字触发截图”。
  • 手柄在净化谜题里被映射为方向键，在其他对话框里被映射为焦点漫游，两种含义不会互相污染。
自动化能证明什么：组件测试用角色、可访问名称和焦点顺序断言标题、设置、帮助与覆盖层， 快捷键与 手柄采样也有确定性测试。 但屏幕阅读器实机朗读、实体手柄完整听测与真人操作舒适度仍是外部门槛，不能由 jsdom 断言代替。
