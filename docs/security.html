Security boundaries

桌面应用仍然有浏览器边界、文件边界与供应链边界

“离线单机”不等于没有攻击面。WebView 内容、IPC 参数、本地 JSON、文件路径、插件权限、依赖安装和发布产物都需要明确边界。

Capability / ACL

default.json 只授权 main 窗口需要的 core 关闭窗口、保存对话框、导出文件定位，以及限定在 $APPLOG 下的日志目录打开能力。 存档与日志插件只由 Rust 后端使用，不向 WebView 暴露；未使用的直接文件系统插件已经移除。

CSP

配置限制默认资源、图片、样式、字体和连接来源，只开放 Tauri IPC 所需 scheme。 unsafe-inline 目前只用于样式；脚本没有放开远程源或 inline 执行。

边界校验

Rust 设置先验证范围；前端 IPC 与证据导入按 schema；存档验证跨字段一致性；性能文本有长度上限。

隐私最小化

性能记录不保留逐帧路径，M2 工具只用 P01–P05 匿名编号，不联网、不自动上传、不采姓名账号。

pnpm desktop:verify-security 会拒绝远程开发源、CSP 通配符或 unsafe-eval、多余 capability、越界路径以及重新注册直接文件系统插件；它也是 pnpm check 的固定阶段。

文件导出的信任边界

路径来自用户主动保存对话框，Rust 负责实际写入。错误需要带操作上下文，但不能回显秘密内容。 应用不递归扫描用户磁盘，也不在后台删除目录。发布脚本默认写入项目的 output，也接受显式指定的输出目录； 发布阶段只清理本次创建的签名临时目录、已核验的候选暂存与替换备份；分别检查目标边界、文件清单和链接。 独立的 pnpm clean 只处理固定的项目构建目录，不接触玩家存档或任意用户目录。

依赖与构建供应链

  • pnpm 与 Cargo 锁文件提交入库，CI 使用 frozen/locked 模式。
  • pnpm audit 检查 JavaScript 公告；高风险传递依赖通过精确 override 修补，并重新生成锁文件。
  • 只允许必要的包安装脚本（Biome 与 esbuild），减少任意生命周期脚本执行面。
  • 代码签名证书只从当前用户证书库按指纹读取；PFX、密码和私钥绝不进入仓库或日志。
  • 候选包与生产包在清单中明确区分；未签名文件不能因为哈希正确就宣称生产发布。

怎样读依赖审计结果

JavaScript 审计不能代表 Rust 也已经检查。Rust 锁文件要对照 RustSec 或 OSV 公告，并用 cargo tree --locked --target x86_64-pc-windows-msvc -i 包名 核实 Windows 实际依赖链。 “锁文件里出现”“目标平台会用到”“存在可触发缺陷”和“停止维护”是不同结论，不能混在一个漏洞数量里。

对已经修复的公告，升级到兼容的修复版本后重跑测试；对没有修复版本的传递依赖，记录上游链路和影响， 评估替换或升级成本。一次查询未发现公告只代表当时数据库的结果，不是永远安全的承诺。 当前检查结果与待跟进项统一记录在 工程进展。
