Tauri 2

Tauri：原生外壳不是一个打包按钮

Tauri 把系统 WebView、Rust 进程、窗口、菜单、托盘、插件和权限系统装配成一个桌面应用。 它的核心价值不是“把网站变 EXE”，而是以明确授权的 IPC 把 Web UI 与原生能力连接起来。

Builder 启动顺序

  1. 安装 panic logger，使未捕获 Rust panic 进入诊断日志；
  2. 安装 single-instance，第二次启动时聚焦主窗口；
  3. 安装 log、store、dialog 和 opener 四个插件——注意这里没有文件系统插件，导出写盘由 Rust 命令自己完成；
  4. 构建原生菜单并把点击转发为前端事件；
  5. 在 setup 中载入设置、创建 AppState、注册托盘并启动魔法场任务；
  6. 通过 generate_handler! 注册命令；
  7. generate_context!() 嵌入编译期配置并进入事件循环。

托管状态 State<'_, AppState>

app.manage(state) 把一个线程安全值交给 Tauri 容器。命令形参中的 State 是带生命周期的借用句柄，命令不能把它任意保存到全局。AppState 内部再用 Arc/Mutex 管理共享所有权与可变性。

插件与动态导入

Rust 插件提供原生实现，前端对应 JS 包提供类型安全调用。保存对话框、路径和 opener 只在 Tauri 分支动态导入， 既避免浏览器开发模式执行原生 API，也把可选代码移出首屏 bundle。插件装上并不等于前端自动有权限，仍需 capability 授权。

窗口、菜单与单实例

tauri.conf.json 定义主窗口尺寸、最小尺寸、背景色、居中和 Win11 Mica； 不支持 Mica 的系统会优雅忽略。原生菜单和托盘使用稳定 id，前端统一处理动作。二次启动不会创建第二个世界实例， 而是显示、取消最小化并聚焦现有窗口，避免并发写存档。

Tauri 路径基准的容易混淆点

before*Command

运行 cwd 是包含 Tauri 配置目录的父目录，即 crates/，所以使用 pnpm -C .. dev/build 才回到仓库根。

frontendDist

它相对配置文件 crates/dream-builder/tauri.conf.json，所以是 ../../apps/desktop/dist。两者不是同一个基准。

Windows WebView runtime

WebView2：使用 Evergreen，不固定运行时版本

Windows 打包版的前端确实运行在 Microsoft Edge WebView2 Runtime 中，但 React 代码没有直接创建或调用 CoreWebView2。调用链由 Tauri → tauri-runtime-wry → Wry → WebView2 COM 完成；前端面对的是标准 Web API 和 Tauri API，而不是某个特定版本的 WebView2 SDK 对象。

结论：不锁定 WebView2 Runtime 版本是本项目正确的默认策略。Evergreen Runtime 由 Windows/ Microsoft Edge Update 维护，各用户在某一时刻的补丁版本可能不同，因此无法也不应要求“所有机器严格同一 WebView2 版本”。 应统一的是受支持行为、Web 标准与回归测试，不是运行时补丁号。

当前配置到底做了什么

"webviewInstallMode": {
    "type": "downloadBootstrapper",
    "silent": true
  }

这是 Tauri 的 Evergreen 引导安装模式：安装器检查运行时，缺失时由 Microsoft bootstrapper 获取合适的 Evergreen Runtime； 已安装时应用直接使用系统运行时。配置没有 fixedRuntime 路径，也没有版本字段。 verify-version-contract.ps1 会阻止误改成固定运行时。

方案优点代价本项目
Evergreen bootstrapper体积小、持续安全更新、Windows 10/11 普遍可用用户补丁版本不同；首次缺失时需要获取运行时采用
Offline installer安装时不依赖网络，仍安装 Evergreen安装包更大；需要随包维护引导文件仅离线部署需求明确时评估
Fixed Version每台机器使用完全相同引擎约增加约 180MB、应用自行承担安全更新与兼容维护不采用

开发浏览器与发布 WebView 的差异

  • pnpm dev 只是 Vite 服务器；你用 Chrome 打开就是 Chrome，用 Edge 打开就是 Edge，不自动变成 WebView2。
  • pnpm tauri dev 和安装后的 EXE 才由 Tauri 创建 WebView2 原生窗口，并启用 IPC、菜单和插件。
  • 因此必须同时做浏览器快速测试和真实 Tauri 冒烟；只在 Chrome 通过不能证明 WebView2 原生集成通过。
  • WebView2 与 Edge 共用 Chromium/平台技术，但 Runtime 是面向嵌入式应用的独立安装与更新通道。

怎样验证而不错误锁版本

  1. 静态验证配置是 downloadBootstrapper 且不存在 fixed path；
  2. 在支持的最低/当前 Windows 环境安装并首次启动；
  3. 确认 msedgewebview2.exe 子进程、原生 IPC、WebGL、音频与导出工作；
  4. 记录测试时的 Windows 与 Runtime 版本用于复现，但不要把该值写成应用启动的硬性等号；
  5. WebView2 大版本变化后用 CI、目标机和干净账户回归关键流程。
