从源码到可安装候选包的证据链

Tauri 构建会先产出 Rust/前端组合的 dream-builder.exe，再由 NSIS 生成当前用户安装包。 项目发布脚本在其上增加版本、源码状态、哈希、签名和文件集检查，防止拿错旧产物。

独立验证来源、哈希、签名、精确文件集

候选包的六个文件

  • Dream-Builder-Fantasy-Tree_1.0_x64.exe：便携入口；
  • Dream-Builder-Fantasy-Tree_1.0_x64-setup.exe：推荐 NSIS 安装器；
  • LICENSE.txt 与 README-zh-CN.md；
  • SHA256SUMS.txt：四个交付载荷的摘要；
  • release-manifest.json：schema 5、唯一产品版本、来源提交、源码树指纹、文件和签名状态。

源码指纹为何不只看 Git commit

本地候选可能在 dirty worktree 构建；只记 HEAD 会把多个不同源码状态写成同一身份。脚本枚举受 Git 管理和未忽略文件， 对路径、大小与 SHA-256 形成排序索引，再计算整棵源码树指纹。产物生成后任何源文件变化都会让独立验证拒绝旧清单。

候选、生产和签名

类型允许状态可以怎样称呼
本地候选显式允许 dirty；EXE 必须明确 NotSigned；清单记录 sourceDirty开发候选，不得公开宣称正式版
干净候选干净提交、全部门禁、未签名可复核发行候选，仍非生产分发
生产包干净源码、证书库有效代码签名、时间戳、两份 EXE 均 Valid满足其余人工门槛后才可正式发布

安装与卸载合同

release-install-state.ps1 在安装后检查唯一卸载项、 两段式版本 1.0、安装目录、主 EXE 和快捷方式；卸载后要求卸载项、程序目录、快捷方式和进程全部消失。 玩家数据可按升级/诊断政策保留，脚本只报告其存在，不读取或删除。完整手册见 release-runbook.md。
