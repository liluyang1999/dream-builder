卸载与数据保留边界。前一轮 [2026-08-09 证据](2026-08-09-release-1.0-lifecycle.md) 保留作历史对照。

结论：采集时构建通过 M2 目标设备性能门禁。M2 总门禁仍未完成，尚未取得 5 名符合资格玩家的无提示观察记录。

`pnpm m2:verify` 会只读复算原生报告哈希，并重新检查十分钟时长、Tauri/Rust 来源、加载/净化阶段与帧率预算。归档清单保留当时 EXE/安装器的哈希、大小和构建时间作为身份，但旧二进制不纳入仓库，且 `target/release/` 会被后续构建覆盖；因此该命令不会把当前 EXE 冒充旧证据，也不会启动已失去绑定关系的文件。

开始新的五人观察前，应从同一个当前 1.0 候选构建出发，先运行 `pnpm release:verify`，再把该候选的工作树标识与 EXE SHA-256 填入观察包和证据工作台。五场必须使用完全相同的文件；候选若改变，观察绑定与受影响的性能阶段都要重新采集。
