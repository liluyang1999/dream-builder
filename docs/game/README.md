## 一句话愿景

玩家作为一名能听见森林记忆的“小小守林人”，在一个精致、温暖的卡通林地里探索、收集光种、净化失色节点，并亲眼看见中央智慧树与周围生态逐步复苏。

目标不是先做一张庞大的开放世界，而是先做一个让人愿意反复停留、截图和完成第二轮探索的高密度盒庭森林。

## 当前项目全貌

当前版本已经证明了确定性程序化树、Rust/Tauri 双进程边界、React/R3F 互动渲染和浏览器无后端回退。最初的 M1 灰盒已演进为分层卡通森林：可移动守林人、相机相对输入、第三人称环绕镜头、边界/障碍碰撞、中央智慧树、溪流、蘑菇坡、遗迹门、成片植被和程序化环境装饰共同组成首章盒庭。原有可点选细节、魔法粒子、Bloom、截图和导出收纳在玩家优先 HUD 的“森林工坊”中。

它已经从观察器变成可独立完成的短篇游戏：玩家从标题界面继续或开始新旅程，发现并收集三枚光种，聆听森林记忆，完成可取消、失败不扣资源的四拍方向净化，原子地触发智慧树成长、地表提亮、音景变化和章节门解锁，并在结尾选择继续漫游或安全重开。五处安全检查点会自动记录并成为重新载入与 `R` 重置位置。v2 本地存档包含检查点与已读记忆，可迁移一致的 v1 存档；最近有效备份、损坏隔离和恢复提示避免静默丢档。

自动化与真实 Chromium 已覆盖光种、空间记忆、检查点触发、错误净化重置、完成态和刷新恢复；1.0 原生候选版另已覆盖标题、设置、制作信息、诊断日志、单实例、暂停和退出。当前 1.0 干净提交候选也在目标 Windows 用户下完成 NSIS 安装、同版重装、真实安装路径首次启动、WebView2 进程树、单实例、正常退出与卸载闭环，卸载后保留用户数据且无程序残留；详细证据见 [2026-08-10 · 1.0 Windows 安装生命周期](evidence/2026-08-10-release-1.0-lifecycle.md)。帮助页内提供固定内存、十分钟自动停止、可导出 JSON 的性能记录器，并会单独汇总重新生成与净化阶段；显式 `?tool=m2-evidence` 开发入口提供不进入玩家 HUD 的本地证据工作台，用于汇总匿名五人观察并拒绝不完整或不匹配的报告。2026-07-23 的目标 Windows 设备原生报告已经归档并通过帧率、时长与关键阶段门禁。主要产品外部缺口现已收敛为五人观察、实体手柄听测、干净 Windows 账户安装/覆盖升级和正式代码签名；这些门槛通过前不得宣称生产发布完成。

## 产品支柱

1. **走进去，而不只是看着它。** 所有核心发现都应通过移动、接近和环境线索完成。
2. **每次行动都让森林变得更美。** 净化、收集和成长必须产生清楚的视觉、声音与生态反馈。
3. **舒适但不空洞。** 不做强惩罚战斗；用路线选择、轻谜题、发现顺序和隐藏记忆提供思考空间。
4. **小世界，高密度。** 首章控制在一个中央林地与三条短支路，优先打磨触感、节奏与重访价值。
5. **种子塑造风貌，不破坏叙事。** seed 可以改变植被、装饰与光种分布，但关键路径、可达性和章节节奏必须稳定。

## 核心循环

```text
观察环境 → 走近线索 → 收集光种 → 解开/净化节点
      ↑                                  ↓
发现新支路 ← 世界变亮、生态回应 ← 智慧树成长并解锁能力
```

一次最小循环应在 60–120 秒内完成；一次 10–15 分钟的游玩应包含三次小循环、一次明显的世界变化和一个值得截图的收束时刻。

## 首个垂直切片边界

- 单人、离线、第三人称；键鼠优先，并支持标准手柄输入。
- 一个约 80×80 米的盒庭林地：中央智慧树、溪流支路、蘑菇坡、遗迹门。
- 三枚光种、一个净化节点、一次智慧树成长、一个记忆片段。
- 没有战斗、联网、建造、角色换装、无限开放世界或复杂经济系统。
- 现有场景导出与 seed 工具保留为开发/创作能力，不承担玩家主循环。

详细的十分钟体验和系统合同见 [首个垂直切片](vertical-slice.md)；真人门禁应直接使用 [M2 无提示可玩性观察协议](m2-playtest.md)。

## 里程碑与完成定义

| 阶段 | 交付结果 | 必须通过的验收证据 |
|---|---|---|
| M0 稳定基线 | 开发/生产均可启动；前后端 seed 一致；监听无泄漏；浅色主题可读；CI 可复现 | 全部 TS/Rust 门禁；真实 Chromium 开发与生产冒烟；CI 配置入库 |
| M1 能走的森林 | 玩家、第三人称相机、统一输入、基础碰撞、灰盒林地 | 键盘完整走一圈；不能穿越边界/关键障碍；相机不进入地面；重置可恢复 |
| M2 可玩的循环 | 光种、净化节点、成长反馈、目标 HUD、会话进度 | 新玩家在无口头提示下完成十分钟流程；状态转换单测；重新载入可恢复进度 |
| M3 美术垂直切片 | 手绘卡通材质、植被层次、昼夜氛围、音频和动效反馈 | 目标硬件稳定帧率；三处地标一眼可辨；前后对比与性能采样归档 |
| M4 首章内容 | 三条支路、记忆叙事、完整引导、设置与可访问性 | 30–45 分钟首章从新档到结尾可完成；键鼠/手柄流程；存档迁移与损坏恢复测试 |
| M5 可发布版本 | 性能、崩溃恢复、签名/安装/升级、发行素材 | 干净 Windows 虚拟机安装/升级/卸载；长时间运行；签名产物与回滚说明 |

只有在同一阶段的行为、测试和真实运行证据都通过后，才能把阶段标记为完成。视觉截图不能替代可玩性，单元测试也不能替代真实 WebGL/Tauri 运行。

## 技术演进原则

- `App.tsx` 继续只做生命周期与跨系统编排；游戏规则进入纯 TypeScript 领域模块，R3F 组件只做呈现和输入适配。
- 玩家输入先归一化为 `MoveIntent`/`ActionIntent`，再驱动固定步长运动，避免把键盘事件散落在组件中。
- 第一阶段使用简单圆柱/胶囊近似与显式障碍，不引入物理引擎；只有斜坡、动态刚体或大量碰撞证明现有方案不足时才评估依赖。
- Rust 负责可持久、可重放的世界数据与原生能力；逐帧运动和相机留在前端，避免高频 IPC。
- 所有世界进度都采用带版本号的可迁移快照；程序化装饰可重建，玩家获得物与章节状态不可只靠 seed 推导。
- 性能预算从 M1 开始记录：当前内置 WebGL 探针汇总 CPU 观察到的帧间隔、draw calls、三角形、可用的 JS 堆峰值和首个场景帧时间；它不能取得 GPU 帧时间，若门禁需要该指标，必须在目标设备上另用 GPU 分析器补充并与 JSON 报告一起归档。

## 近期决策顺序

1. 先完成 M0 并留存可复现证据。
2. M1 只做“移动手感 + 相机 + 可读灰盒”，不提前制作大批美术资产。
3. M2 用占位视觉证明十分钟循环有趣，再进入 M3 风格化生产。
4. 每个里程碑结束做一次小规模可玩性观察；事实与玩家行为优先于设计文档中的猜测。
