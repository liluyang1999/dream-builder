# M2 无提示可玩性观察协议

本协议用于验证灰盒循环是否真的可理解，而不是验证主持人是否能把玩法讲清楚。M2 只有在行为观察、自动化门禁和目标设备运行证据同时通过后才能完成。

## 样本与通过条件

- 观察 5 名此前未接触本项目、未阅读设计文档的玩家。
- 至少 4/5 人在 90 秒内自行找到第一条路线，且没有把 seed 输入或导出按钮当成主目标。
- 每位玩家都应在不接受操作或路线提示的情况下，于 12 分钟内完成三枚光种、净化和世界复苏。
- 所有观察到的可达位置都能通过继续行走或 `R` 返回安全点恢复；任何卡死都直接记录为缺陷。
- 同一目标 Windows 设备上保留一份连续十分钟性能记录，单独标记加载和净化峰值。

## 每位玩家开始前

1. 在仓库根目录运行 `pnpm m2:verify`，确认目标 EXE 与性能报告哈希均通过；再运行 `pnpm m2:playtest` 启动经过性能验证的同一构建。脚本若发现旧进程会拒绝启动，主持人应手动确认并关闭旧会话，不能强制结束未知状态的进程。
2. 使用同一构建和同一台目标设备，记录构建清单、分辨率、缩放、CPU、GPU 和驱动版本。
3. 主持人按 `?` 打开帮助，选择“重新开始本章”，再选择“确认重开”。界面重新显示欢迎提示后停止操作。
4. 确认计时器归零、录屏或观察表已经就绪；不采集姓名、账号或无关个人信息。
5. 只对玩家说：“请体验这段森林旅程，并完成你认为的主要目标。过程中我不会提供操作或路线提示。”

## 观察规则

- 不念出界面文字，不指出按键、光种、记忆、检查点或遗迹位置。
- 不纠正走错路。若玩家主动提问，只回答“请按你的理解继续尝试”。
- 只有出现身体不适、应用崩溃或无法恢复的技术故障时才中止；中止原因必须记录。
- 玩家完成、主动放弃或达到 12 分钟时结束。结束后再询问他们认为的目标、最困惑处和最想截图的时刻。

## 汇总与决策

完成 5 次观察后，先按行为频次归类问题，再修改游戏。优先级顺序为：阻断完成的问题、4/5 门槛失败、重复出现的路线误读、反馈不清、纯偏好。每次修改后保留原始记录，并对受影响的门槛重新观察；不得用设计意图覆盖玩家实际行为。

性能记录至少汇总平均帧率、1% low 或等价低分位、最长帧、加载峰值、净化峰值和是否出现持续卡顿。M2 灰盒通过线固定为：平均 ≥55 FPS、1% Low ≥30 FPS、超过 50 ms 的帧 ≤1%，且人工未观察到持续卡顿。没有目标设备数据时，M2 仍保持进行中。

## 目标设备性能采集

这是一轮独立的技术走查，不计入 5 名新玩家的无提示样本：

1. 在目标 Windows 设备与拟交付的 Tauri 构建中，按 `?` 打开帮助，选择“性能记录”，再选择“开始 10 分钟记录”。关闭面板不会停止记录。
2. 开始后立即重新生成一次世界，以产生 `scene-load` 区间；随后按正常路线完成三枚光种和净化，以产生 `cleansing` 区间。不要切到后台或改变窗口尺寸，除非这正是待验证场景。
3. 等待记录器自动停止；若应用崩溃或记录被提前停止，保留报告但将该轮标为不满足十分钟门槛，并重新采集。
4. 重新打开“性能记录”，导出 JSON。把报告与构建标识、设备型号、分辨率、缩放、CPU、GPU、驱动版本及人工观察到的持续卡顿一并归档；不记录姓名、账号或无关个人信息。
5. 核对 `completedTargetDuration` 为 `true`，并确认报告同时出现 `scene-load` 与 `cleansing` 阶段。内置探针不提供 GPU 帧时间；若验收需要该值，另附目标设备 GPU 分析器结果。

当前 M2 目标机基线（2026-07-23）为 Lenovo `20TKCTO1WW`、Intel Core i7-10850H、NVIDIA GeForce GTX 1650 Ti Max-Q（驱动 `32.0.15.7357`）、31.8 GiB 内存、3840×2160 @ 59 Hz、Windows 缩放 250%。Tauri 窗口采用默认 1280×800 配置；报告内实测 WebView 渲染视口为 1220×744 CSS px，设备像素比为 2.625。系统缩放、渲染视口和 WebView DPR 是三个独立事实，证据包不得互相推导或改写。若更换设备、缩放、窗口尺寸或有效 DPR，必须建立新的设备代号并重新采集，不能与本基线混为一组。

本基线的首份合格原生报告及构建绑定信息已归档在 [M2 目标机性能证据](evidence/README.md)。这只完成技术性能门禁；5 名首次接触玩家的观察记录尚未产生，因此 M2 总门禁仍保持进行中。

## 本地证据工作台

1. 从仓库根目录运行 `pnpm dev`，在浏览器打开 `http://127.0.0.1:1420/?tool=m2-evidence`。这是独立主持人工具，不会出现在玩家 HUD。
2. 填入构建版本、工作树标识和实际 `dream-builder.exe` SHA-256；设备字段默认对应上述目标机，但仍应逐项复核。
3. 导入原生性能 JSON，并按观察表填写 P01–P05。空白里程碑保持为空，不得用推测时间补齐。
4. 工作台会检查样本资格、4/5 首条路线、5/5 无提示完成、卡死、原生运行时、十分钟时长、关键阶段、窗口缩放和帧率预算。失败结果会原样保留。
5. 所有结构字段完整后导出 `dream-builder-m2-evidence-YYYY-MM-DD.json`。证据包使用 schema v2，将 Windows 系统缩放与报告实测 DPR 分开记录；只含匿名编号、聚合性能与必要文字观察。不要在自由文本中写姓名、账号、联系方式或无关个人信息。

证据工作台拒绝把浏览器回退、短时报告、缺失净化阶段、逐帧 `samples` 或不匹配的窗口配置判作通过。它只汇总真实观察，不能生成或替代 5 名新玩家样本。
